# Lua の壁紙

壁紙は LuaJIT（Lua 5.1 の文法）で書く。出力（モニター）ごとに独立した Lua の実行環境が作られるので、
モニターごとに乱数も状態も別になる。
壁紙のファイルを保存して読み直すと、乱数の種も新しくなる。読み直す前と同じ乱数の並びにはならない。

```lua
local t = 0

function update(dt)
  t = t + dt
end

function draw()
  clear(0.04, 0.04, 0.04)
  color(1, 1, 1, 0.8)
  circle(screen.w / 2 + math.cos(t) * 200, screen.h / 2, 20)
end
```

## コールバック

どれも省略できる。

| 関数 | 呼ばれるタイミング |
|---|---|
| `load()` | 読み込み直後に 1 回 |
| `update(dt)` | 毎フレーム。`dt` は前のフレームからの秒数（最大 0.25） |
| `draw()` | 毎フレーム、`update` の後 |
| `mousepressed(x, y, button)` | ボタンを押したとき。`button` は `"left"` / `"right"` / `"middle"` |
| `mousereleased(x, y, button)` | ボタンを離したとき |

## 描画関数

座標はピクセル単位で、左上が原点。

| 関数 | 説明 |
|---|---|
| `clear(r, g, b)` | 画面を塗りつぶす。呼ばなかったフレームは黒になる |
| `color(r, g, b, a)` | 以降の図形の色。各値は 0〜1、`a` は省略すると 1 |
| `blend(mode)` | `"alpha"`（既定、普通の重ね塗り）か `"add"`（加算合成） |
| `line(x1, y1, x2, y2, width)` | 端が丸い線。`width` は省略すると 1 |
| `circle(x, y, r)` | 塗りつぶした円 |
| `rect(x, y, w, h, angle)` | 塗りつぶした矩形。`angle`（ラジアン）を渡すと、矩形の中心のまわりに回す（画面上で時計回り）。`angle` は省略できる（下を参照） |
| `image(name, x, y, w, h, angle)` | 画像（下の「画像」を参照）。`w, h` を省くと画像のピクセルサイズで描く。`angle` は `rect` と同じ |
| `subimage(name, sx, sy, sw, sh, x, y, w, h, angle)` | 画像の (sx, sy, sw, sh) の部分（画像のピクセル）を、(x, y, w, h) に描く。`angle` は省略できる |
| `imagesize(name)` | 画像の幅と高さ（ピクセル）を返す。`load()` の中でも使える |

`rect` は `angle` を渡したときだけ、縁にアンチエイリアスを付けて描く（値が 0 でも）。
`angle` を省くと、今までどおり縁にアンチエイリアスを付けずに描く。
そのため、座標が整数でないときは `rect(x, y, w, h)` と `rect(x, y, w, h, 0)` の縁の見た目が少し違う（後者がわずかにぼやける）。
回転させる矩形は、角度が 0 を通るときも見た目が変わらないように、常に `angle` を渡すとよい。例は `examples/tiles.lua`。

描画関数に、表に書いた数より多い引数を渡すとエラーになる（`circle: too many arguments (max 3)` など）。
後ろに付いた `nil` は数えないので、`rect(x, y, w, h, nil)` は `rect(x, y, w, h)` と同じ。途中の `nil`（`rect(x, y, w, h, nil, 1)` など）はエラーになる。

## 画像

ファイルの先頭のコメントに `@image 名前 パス` で画像を指定し、描画関数ではその名前で指す。例は `examples/mosaic.lua`。

```lua
-- @image photo photo.jpg
-- @image dots "my dots.png" filter=nearest wrap=repeat

function draw()
  image("photo", 0, 0, screen.w, screen.h)
  color(1, 1, 1, 0.5)                          -- 色を掛け、半透明にする
  subimage("dots", 0, 0, 16, 16, 100, 100, 64, 64, 0.3)
end
```

- `image(name, x, y)` / `(name, x, y, angle)` / `(name, x, y, w, h)` / `(name, x, y, w, h, angle)` のどれかで呼ぶ。`subimage` は 9 個か 10 個（最後が `angle`）
- `w`・`h` が負なら、左右・上下を裏返して描く
- `color` の色を画像に掛ける（既定の白ならそのままの色）。`blend` も図形と同じように効く
- `subimage` の範囲は画像の外にはみ出してもよい。はみ出した部分は `wrap` の指定に従う（`clamp` なら端の色が伸び、`repeat` なら繰り返す）
- 指定していない名前を使うとエラーになる
- 画像 1 つを図形 1 つとして、1 フレーム 100 万個の上限に数える
- 書ける場所・パス・形式は、シェーダーの壁紙の画像と同じ（シェーダーの壁紙の[「画像」](shader.md#画像)を参照）。`vflip` は指定できない（画像の上が画面の上に来る）
- オプション（どれも省略できる）:

| オプション | 値 | 既定 |
|---|---|---|
| `filter` | `nearest` / `linear` / `mipmap` | `mipmap` |
| `wrap` | `clamp` / `repeat` | `clamp` |

- `wrap` の既定はシェーダーの壁紙（`repeat`）と違う。`repeat` のまま拡大すると、反対側の端の色が縁に混ざるため。画像を敷き詰めるときは `wrap=repeat` を書く
- 1 枚の画像に並べた絵（アトラス）を `subimage` で拡大すると、隣の絵の色が縁に混ざる。避けるには `filter=nearest` にするか、絵の間に余白を置く
- 画像はすべての出力で 1 回だけ読み込み、出力の間で共有する。デコードは壁紙のファイルを読むときに行い、GPU に送るのは最初に描くとき

## 渡される情報

| 変数 | 内容 |
|---|---|
| `screen.w`, `screen.h` | 画面のピクセルサイズ |
| `screen.output` | 出力名 |
| `mouse.x`, `mouse.y` | カーソルの位置 |
| `mouse.inside` | カーソルがこの壁紙の上にあるか（ウィンドウに隠れていない部分だけ） |
| `mouse.left`, `mouse.right`, `mouse.middle` | ボタンを押しているか |
| `mouse.press_x`, `mouse.press_y` | 最後にドラッグを始めた（ボタンを押した）位置。離した後も残る。一度も押していなければ 0 |
| `mouse.dragging` | どれかのボタンを押している間 `true`。離すか、カーソルが壁紙の外に出ると `false` |

`press_x`・`press_y`・`dragging` は、シェーダーの `iMouse` と同じくボタンを区別しない。
左・右・中・4・5 のどれを押してもドラッグを始め直し、どれかを離すとドラッグが切れる。
座標は `mouse.x`・`mouse.y` と同じく左上が原点（`iMouse` と違い y を反転しない）。
例は `examples/slingshot.lua`。

## キーボード

`keyboard.down(name)` で、そのキーを押しているかを読む。例は `examples/keys.lua`。

```lua
function update(dt)
  if keyboard.down("space") then
    -- ...
  end
end
```

キーの名前は LÖVE と同じ形。

| 名前 | キー |
|---|---|
| `"a"`〜`"z"`、`"0"`〜`"9"` | 文字と数字のキー |
| `";"`、`"-"`、`"@"` など | 記号のキー（キーに書かれた 1 文字） |
| `"space"`、`"return"`、`"escape"`、`"backspace"`、`"tab"` | |
| `"left"`、`"right"`、`"up"`、`"down"` | 矢印キー |
| `"lshift"`、`"rshift"`、`"lctrl"`、`"rctrl"`、`"lalt"`、`"ralt"`、`"lgui"`、`"rgui"` | 修飾キー（左右を区別する。AltGr は `"ralt"`） |
| `"insert"`、`"delete"`、`"home"`、`"end"`、`"pageup"`、`"pagedown"` | |
| `"f1"`〜`"f24"` | ファンクションキー |
| `"kp0"`〜`"kp9"`、`"kp."`、`"kp/"`、`"kp*"`、`"kp-"`、`"kp+"`、`"kp="`、`"kpenter"` | テンキー（NumLock に関係なく数字のキー） |
| `"capslock"`、`"numlock"`、`"scrolllock"`、`"pause"`、`"printscreen"`、`"menu"` | |

- キーはキーボードの配列に従う（キーに書かれた文字になる）。Shift などを押していても同じ名前になる（Shift+1 も `"1"`）
- 大文字（`"A"`）や表にない名前（`"enter"` など）を渡すとエラーになる。日本語の入力のキー（変換など）は読めない

キーが届くのは、壁紙にキーボードのフォーカスがあるときだけ。`keyboard.down` を初めて呼んだフレームのあとで、壁紙の layer surface を `keyboard_interactivity` の `on_demand` にして、フォーカスを受け取れるようにする（読み込みのときに呼んでもよい）。フォーカスがいつ来るか（壁紙をクリックしたときなど）はコンポジター次第。ウィンドウがフォーカスを持っている間は、キーは壁紙に届かない。

- キーが届くのは、フォーカスを持っている出力の壁紙だけ（マウスと同じ）。ほかの出力の壁紙では、キーを押していない扱いになる
- フォーカスが外れたら、押しているキーをすべて離した扱いにする
- `keyboard.down` を呼ばない壁紙では、今までどおり `none` のままにし、フォーカスを受け取らない。読み直したときも `none` に戻し、新しいスクリプトが呼んだら、また `on_demand` にする
- コンポジターの wlr-layer-shell がバージョン 4 より古く `on_demand` を使えなければ、警告を出してキーを使えないままにする（`keyboard.down` は常に `false`）

## サンドボックス

壁紙のスクリプトが使えるのは `math`、`string`、`table`、`bit` と基本関数だけ。
`io`、`os`、`require`、`load` 系、`debug`、`ffi`、`jit`、`coroutine`、`getfenv` / `setfenv`、`string.dump` は使えない。
バイトコードは読み込めない（テキストのスクリプトだけ）。
`print` は標準エラー出力に出る。

描画関数（`line` など）は本体側で LuaJIT の `ffi` を使って頂点を直接書き込んでいるので、
1 図形あたり 10ns 弱で描ける（2 万個の図形で、Lua 側の処理は 1 フレーム約 0.2ms）。
`ffi` は描画関数の内側に閉じ込めてあり、壁紙のスクリプトからは触れない。

## エラーと無限ループ

- 起動時に壁紙のファイルを読めなければ（ファイルが無いなど）、エラーを出して終了コード 1 で終了する。実行中にファイルが消えた場合は、保存の途中とみなして、また現れるまで待つ
- 読み込み時や実行時にエラーが起きたら、標準エラー出力に出して、直前のフレームを表示したまま止まる。ファイルを直して保存すれば再開する
- 1 回の呼び出しが長すぎる場合（読み込み 2 秒、毎フレーム 0.25 秒）はエラーとして止める
- 1 フレームに描ける図形は 100 万個まで（画像も 1 つを 1 個と数える）。超えたらエラーとして止める
- 画像の指定の書き間違いや、画像を読めない（ファイルがない・壊れている・大きすぎる）ときも、同じように止まる。画像を直して保存すれば再開する。指定した画像は、読めなかったものも見張っている（zip ファイルで渡したときは、zip ファイルを見張る）
- ただし、JIT コンパイルされたループのうち、描画関数を呼ばないものはこの仕組みでは止められない。スクリプトが 5 秒戻ってこなければ、kagegami は終了コード 3 で終了する（使い方の詳細の[「自動起動」](usage.md#自動起動)を参照）
